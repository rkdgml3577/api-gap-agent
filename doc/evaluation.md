# 평가 방법

동일한 업무 규칙과 명세에서 healthy/buggy/covered 구성을 각각 분석한다.
각 구성은 독립 실행하며 모델명, 판단 횟수, 토큰 수, 시간을 함께 기록한다.
모델은 평가 정답 파일을 읽을 수 없다. 평가기는 분석이 끝난 뒤 정답과 비교한다.

## 지표

- 누락 정확도: 올바른 누락 제안 / 전체 누락 제안
- 누락 재현율: 올바른 누락 제안 / 실제 누락
- 결함 재현율: 발견한 실제 결함 / 실제 결함
- 잘못된 누락 및 결함: 정답에 없는 제안을 별도 기록
- incomplete/error는 완료 분석의 성공으로 취급하지 않음
- 현재 숫자의 평가 단위는 규칙이며 개별 경계값 시나리오 단위가 아님

생성 테스트의 실행 및 관찰은 report.json의 observations에서 확인한다.
후보가 타당한지, 근거 인용이 실제 판단을 지지하는지는 별도의 사람 검토가 필요하다.
covered 사례는 타당한 기존 검증을 누락으로 오판하는지 확인하기 위한 음성 사례다.

## 한계

단일 시연 결과는 성능 추정치가 아니다. 구성별 반복 실행과 더 다양한 정답 사례가 필요하다.
아직 고정 파이프라인 baseline과의 자동 비교 및 인용 의미 정확도 자동 채점은 구현하지 않았다.
